# 2013-01-03: окно с TTF — сломанный рефакторинг

Главный исторический артефакт: последняя версия «той самой» программы.
SDL 1.2 + SDL_ttf, моноширинный DejaVu Sans Mono Bold, зелёный текст
на чёрном, массив фраз, самодельный коэффициент совпадения.

## Что случилось

Ночью 3–4 января 2013 обработку событий вынесли в отдельный файл.
Получилось два состояния одного исходника:

```
hello_c_backup_030113.7z   655 строк   ← рабочее
hello.c                    649 строк   ← сломано
```

Правки, которые всё сломали:

```diff
+      process_events();
+      /*
       while(SDL_PollEvent(&event)){    ← весь разбор событий
         ...                            ← закомментирован
       }
+      */
```

А `helleventcontrol.c` содержит пустую заглушку: `switch` по типу события
с двумя `break` и без единого действия.

**Итог:** программа рисуется, но не реагирует ни на что.

Подтверждение из дизассемблера `hello.exe`: функция `process_events`
по адресу `0x401C76` сравнивает тип события с `2` (`SDL_KEYDOWN`) и
`12` (`SDL_QUIT`) и в обоих случаях просто выходит из `switch`.

```bash
python ../../tools/re/pe_info.py hello.exe
python ../../tools/re/pe_strings.py hello.exe --utf8
```

## Ещё две мины

1. `hello.c` в UTF-8, `helleventcontrol.c` в **cp1251**. Одна единица
   трансляции, две кодировки. Компилятор проглотил, потому что весь
   cp1251-текст — в комментариях.
2. `#include "keysim.c"` и `#include "acsman.c"` — включение `.c` в `.c`.
   Работает, но ломает раздельную компиляцию.

## Строки, которых нет в бинаре

В `hello.c` есть `"Иди нахуй, окда?"`, но в `hello.exe` её **нет** —
она внутри закомментированного блока. А `"Здарова, "`, `" ёпта"` и
`"ВНЕЗАПНО: Доступ есть %i"` в бинаре есть. Ещё одно подтверждение,
что exe собран именно из сломанной версии.

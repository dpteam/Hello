Файлы: `src/text_metrics.c`, `src/markov.c`, `src/chat.c`.

## 1. Похожесть текстов

Текст сначала нормализуется: нижний регистр, удаление пунктуации и пробелов,
разбиение на кодпоинты UTF-8. Дальше работаем с массивами `uint32_t`.

### 1.1 Коэффициент Дайса

Мера перекрытия двух множеств:

```
D(A, B) = 2·|A ∩ B| / (|A| + |B|)
```

Для биграмм (пар соседних символов):

```
"привет" → {пр, ри, ив, ве, ет}     |A| = 5
"приветик" → {пр, ри, ив, ве, ет, ти, ик}  |B| = 7
A ∩ B = {пр, ри, ив, ве, ет}        |A∩B| = 5

D = 2·5 / (5+7) = 10/12 ≈ 0.833
```

Свойства: `D = 1` для одинаковых, `D = 0` для непересекающихся,
симметрична. Устойчива к перестановкам слов («дела как» vs «как дела»
дадут высокий балл).

**В коде:** `tm_dice_bigrams`. Биграммы сортируются и сливаются —
`O(n log n)` вместо `O(n²)`.

Для строки из одного символа биграмм нет, поэтому используется сам
символ с установленным старшим битом — иначе «да» и «да» не совпали бы.

### 1.2 Коэффициент Жаккара

```
J(A, B) = |A ∩ B| / |A ∪ B|
        = |A ∩ B| / (|A| + |B| − |A ∩ B|)
```

Жёстче Дайса: сильнее штрафует за лишние элементы. Для примера выше:

```
J = 5 / (5 + 7 − 5) = 5/7 ≈ 0.714
```

Используется в тестах как контроль и доступна через API, но в итоговую
оценку не входит — Дайс на коротких фразах ведёт себя стабильнее.

### 1.3 Косинус по униграммам

TF-векторы по символам:

```
cos(a, b) = Σ tf_a(i)·tf_b(i) / (‖tf_a‖ · ‖tf_b‖)
‖tf‖ = sqrt(Σ tf(i)²)
```

Ловит совпадение набора букв независимо от порядка. Слабее биграмм,
поэтому в композит не входит, но полезна для диагностики.

### 1.4 Расстояние Левенштейна

Минимальное число вставок, удалений и замен:

```
         ⎧ i,                    если j = 0
         ⎪ j,                    если i = 0
D(i,j) = ⎨ D(i−1, j−1),          если aᵢ = bⱼ
         ⎪ min(D(i−1,j) + 1,     удаление
         ⎩     D(i,j−1) + 1,     вставка
               D(i−1,j−1) + 1)   замена
```

Пример: `кот → кит` = 1 (замена о→и).

**Ранний выход.** Если минимальное значение в текущей строке превысило
`max_distance`, дальше считать бессмысленно — возвращаем `max_distance + 1`.
Плюс отсев по разнице длин в начале.

**Память.** Две строки вместо матрицы: `O(min(n,m))`.

### 1.5 Расстояние Дамерау–Левенштейна

Добавляет транспозицию соседних символов:

```
если aᵢ = bⱼ₋₁ и aᵢ₋₁ = bⱼ:
    D(i,j) = min(D(i,j), D(i−2, j−2) + 1)
```

Пример: `форма → фрома` = 1 транспозиция, а не 2 замены.

Требует доступа к `i−2`/`j−2`, поэтому нужна полная матрица. Чтобы не
тратить память, для строк длиннее 256 символов деградируем до Левенштейна —
на таких длинах опечатки уже не критичны.

### 1.6 Джаро–Уинклер

```
J(a,b) = (1/3)·(m/|a| + m/|b| + (m − t/2)/m)
JW = J + ℓ·p·(1 − J)
```

где:
- `m` — число совпавших символов в окне `⌊max(|a|,|b|)/2⌋ − 1`,
- `t` — число перестановок в совпавших парах,
- `ℓ` — длина общего префикса (не больше 4),
- `p = 0.1` — вес префикса.

Пример: `марта` vs `мартышка`

```
m = 5 (марта совпадает целиком)
t = 0
J = (1/3)(5/5 + 5/8 + 5/5) = (1/3)(1 + 0.625 + 1) ≈ 0.875
ℓ = 5 → ограничено 4
JW = 0.875 + 4·0.1·(1 − 0.875) = 0.875 + 0.05 = 0.925
```

Бонус за префикс — ключевая часть: русские слова часто отличаются
окончаниями, и общий корень в начале — сильный сигнал.

### 1.7 Композитная оценка

```c
score = 0.50·Дайс + 0.25·JW + 0.25·(1 − Левенштейн/max_len)

if (одна фраза целиком входит в другую)
    score += 0.16

score = min(score, 1.0)
```

Веса подобраны так, чтобы:
- структурное совпадение (Дайс) доминировало,
- начало слова (JW) спасало короткие запросы,
- опечатки (Левенштейн) не обнуляли совпадение.

Бонус за вложенность решает конкретный случай: «дела» должна находить
«как дела», хотя Дайс на такой паре даёт всего ~0.5.

## 2. BM25

Классическая функция ранжирования из информационного поиска
(Robertson & Zaragoza, 2009).

```
score(D, Q) = Σᵢ IDF(qᵢ) · (f(qᵢ,D) · (k₁ + 1)) /
                          (f(qᵢ,D) + k₁ · (1 − b + b · |D|/avgdl))

IDF(qᵢ) = ln(1 + (N − n(qᵢ) + 0.5) / (n(qᵢ) + 0.5))
```

где:
- `N` — число документов (фраз в памяти),
- `n(qᵢ)` — в скольких документах встречается слово,
- `f(qᵢ,D)` — частота слова в документе,
- `|D|` — длина документа в словах,
- `avgdl` — средняя длина,
- `k₁ = 1.4` — насыщение частоты,
- `b = 0.72` — сила нормализации по длине.

### Зачем `k₁`

Без насыщения слово, встретившееся 100 раз, весило бы в 100 раз больше
слова, встретившегося один раз. С `k₁` рост ограничен: при `f → ∞`
числитель и знаменатель растут одинаково, вклад стремится к `IDF·(k₁+1)`.

### Зачем `b`

Длинная фраза содержит больше слов случайно, поэтому её нужно штрафовать.
`b = 1` — полная нормализация, `b = 0` — никакой. `0.72` — компромисс.

### Как встроено

BM25 нормируется в `0..1` через `x/(x+3)` (насыщающая функция) и
смешивается с похожестью:

```
final = 0.70·similarity + 0.30·(bm25/(bm25+3))
```

Почему `x/(x+3)`: BM25 не ограничен сверху, а смешивать надо сопоставимые
величины. `3` подобрано так, чтобы типичный BM25 (2–5) давал 0.4–0.6.

### Пример

Память: `["Да", "Привет", "Я программист"]`, запрос `"я программист"`.

```
N = 3, avgdl = 1.33

Для "программист":
  n = 1, |D| = 2, f = 1
  IDF = ln(1 + (3−1+0.5)/(1+0.5)) = ln(1 + 1.667) ≈ 0.981
  denom = 1 + 1.4·(1 − 0.72 + 0.72·2/1.33) = 1 + 1.4·0.795 ≈ 2.113
  вклад = 0.981 · (1·2.4)/2.113 ≈ 1.114

Для "я":
  n = 1, IDF ≈ 0.981, f = 1, denom ≈ 2.113
  вклад ≈ 1.114

BM25 ≈ 2.23 → norm = 2.23/(2.23+3) ≈ 0.43
```

## 3. Цепь Маркова

### 3.1 Модель

Цепь порядка `k` предсказывает следующее слово по `k−1` предыдущим:

```
P(wₙ | w₁…wₙ₋₁) = P(wₙ | wₙ₋ₖ₊₁…wₙ₋₁)
```

Вероятность всей последовательности:

```
P(w₁…w_N) = Πₙ P(wₙ | wₙ₋ₖ₊₁…wₙ₋₁)
```

Для `k = 2` (биграммы):

```
P(котиков | я, люблю) = count("я люблю котиков") / count("я люблю")
```

### 3.2 Сглаживание: «глупый бэкофф»

Проблема: если пара `(я, люблю)` ни разу не встречалась, вероятность 0
и генерация останавливается.

Решение (Brants et al., 2007) — пробовать контекст короче:

```
P(w | a,b) = ⎧ P₂(w | a,b),  если count(a,b,·) > 0
             ⎨ P₁(w | b),    если count(b,·) > 0
             ⎩ P₀(w | <s>),  иначе (начало предложения)
```

Просто, предсказуемо, и для 4000 фраз разницы с Kneser-Ney не видно.

### 3.3 Температура

Распределение переходов искажается степенью:

```
p_i = w_i^(1/T) / Σⱼ w_j^(1/T)
```

где `w_i` — счётчик перехода.

| `T` | `1/T` | Эффект |
|---|---|---|
| 0.5 | 2.0 | почти всегда самое частое продолжение |
| 1.0 | 1.0 | исходные частоты |
| 1.6 | 0.625 | редкие переходы получают шанс |
| → ∞ | → 0 | равномерное распределение |

При `T → 0` распределение вырождается в `argmax` — детерминированная
генерация по самому частому пути.

### 3.4 Перплексия

Мера «удивления» модели на тексте:

```
H = −(1/N)·Σₙ log₂ P(wₙ | контекст)
PP = 2^H
```

Интерпретация: `PP = k` означает, что модель в среднем сомневается между
`k` равновероятными вариантами.

Пример:
```
Модель: "кошка сидит на окне и смотрит во двор"

PP("кошка сидит на окне")     ≈ 1.8   ← знакомый текст
PP("трактор пашет поле утром") ≈ 8.4   ← незнакомый
```

Незнакомые слова обрабатываются через OOV-вероятность:

```
P_oov = 1 / (tokens_seen + 1),  ограничено [1e-9, 0.5]
```

Чем больше модель видела, тем меньше она удивляется новому.

### 3.5 Хранение

Словарь: `слово → id`, хеш FNV-1a 64-бит.
Переходы:
- `unigram[id]` — список `(next_id, count)`,
- `bigram_index[(a,b)]` — список `(next_id, count)`.

Токены `0` и `1` — `<s>` и `</s>`, реальные слова начинаются с `2`.

## 4. Выбор ответа

### 4.1 Урновая модель «не повторяться»

Счётчик использований `u_i` уменьшает вес:

```
penalty_i = max(1 / (1 + 0.35·u_i), 0.5)
```

Нижняя граница `0.5` важна: без неё точное совпадение со временем
проигрывало бы случайной фразе, и бот «тупел» бы от собственных ответов.

### 4.2 Взвешенный выбор

Топ-6 кандидатов, отсечение слабых (`score < 0.72·лучший`), затем:

```
p_i = score_i³ / Σ score_j³
```

Куб делает распределение «острым»: лучший кандидат забирает большую часть
вероятности, но не всю. Это даёт вариативность без потери осмысленности.

### 4.3 Импровизация

Если `лучший score < 0.28`, бот либо сочиняет, либо отделывается
встроенной репликой:

```
P(сочинять) = 0.45 · learned/(learned + 12)
```

| Выучено фраз | `P(сочинять)` |
|---|---|
| 0 | 0.00 |
| 3 | 0.09 |
| 12 | 0.23 |
| 50 | 0.36 |
| 500 | 0.44 |

Логика: на пустой памяти сочинять не из чего, поэтому бот честно отвечает
заготовкой. По мере обучения он всё охотнее пробует говорить сам.

### 4.4 Резервуарная выборка

При переполнении памяти (4096 фраз) новая фраза с вероятностью
`max/seen` заменяет случайную выученную.

Свойство: каждая увиденная фраза имеет равный шанс оказаться в памяти
независимо от порядка поступления. Альтернатива «выкидывать старые» дала
бы перекос в сторону последних разговоров.

## 5. Прочее

### 5.1 Энтропия Шеннона

```
H(X) = −Σ p(x)·log₂ p(x)
```

Максимум `log₂ n` достигается на равномерном распределении.
Используется в тестах и для диагностики распределений.

### 5.2 Softmax

```
softmax(x)ᵢ = exp(xᵢ/T) / Σⱼ exp(xⱼ/T)
```

Реализация вычитает максимум перед `exp` — иначе при `x ~ 1000`
происходит переполнение:

```
exp(xᵢ − max) / Σ exp(xⱼ − max)
```

Результат тот же, но без `inf`.

### 5.3 Число сочетаний и вероятность

Не используется, но пригодится для оценки «сколько всего можно сказать»:

```
C(n, k) = n! / (k!(n−k)!)
```

Для словаря 1000 слов и фразы из 8 слов: `C(1000, 8) ≈ 2.4·10¹⁹`
вариантов без учёта грамматики.

### 5.4 Формула Байеса

Основа для будущего «понимания» намерения:

```
P(намерение | слова) = P(слова | намерение)·P(намерение) / P(слова)
```

Пока не реализовано — BM25 и метрики покрывают текущие задачи.

### 5.5 TF-IDF (упрощённый)

Предшественник BM25, без нормализации по длине:

```
tfidf(t, d) = tf(t, d) · log(N / df(t))
```

BM25 его обобщает, поэтому в коде используется только BM25.

### 5.6 Косинусная мера и евклидово расстояние

```
cos(a,b) = a·b / (‖a‖·‖b‖)
‖a − b‖₂ = sqrt(Σ(aᵢ − bᵢ)²)
```

Косинус инвариантен к длине, евклидово — нет. Для текста нужен первый.

### 5.7 Экспоненциальное сглаживание (FPS)

```
fps_new = 0.9·fps_old + 0.1·fps_instant
```

Простое сглаживание, чтобы счётчик в статус-баре не дёргался на каждом кадре.

# Архив: инвентаризация вариантов

`archive/` — не свалка и не «старое, что жалко удалить». Это зафиксированные
варианты идей, каждый со своей судьбой. Основная линия живёт в `src/`,
здесь — то, что либо устарело, либо не пошло, либо было чужим с самого начала.

**Правило:** архивные файлы не редактируются. Даже мат в комментариях,
даже баги, даже cp1251. Это исторические артефакты; переписывать их —
значит терять то, ради чего они хранятся. Всё новое пишется в `src/`.

Ниже — что где лежит и как это определено (по датам PE-заголовков,
символам в бинарях, строкам и диффам исходников).

| `hello_0_04.c` | 358 | + `SDL_Init`, `TTF_Init`, `DrawImage`, `ii_sdlvideomode` |
| `main.c` | 249 | ветка от `hello_0_02a`, копия с правками |
| `hello_console_utf8.c` | 217 | версия `hello_0_02` в UTF-8 (остальные — cp1251) |

`bin/`:

| Бинарь | PE-дата | Собран из |
|---|---|---|
| `hello_030713_1920.exe` | 03.07.2012 19:20:36 | ранний `hello.c` |
| `hello_0_01_030713_1934.exe` | 03.07.2012 19:34:49 | `hello_0.01` |
| `hello_0_01_030713_1942.exe` | 03.07.2012 19:42:58 | `hello_0_01.c` |
| `project1_040713.exe` | 04.07.2012 23:20 | `main.c` (24 585 байт) |

**Что тут интересного.** Функция `analyze()` — прямой предок современной
метрики:

```c
float analyze(char *buffer, char *ptr)
{
    unsigned int equal = 0, notequal = 1;
    while (*buffer) {
        while (*ptr) {
            if (!strncmp(ptr, buffer, 2))   /* сравнение по 2 байта = «биграммы» */
                equal++;
            else
                notequal++;
            *ptr++;
        }
        *buffer++;
    }
    return ((float)equal / (float)notequal);
}
```

То есть **идея биграмм была уже в 2012-м** — только называлась «сравнить
по два байта» и работала на сырых байтах cp1251, а не на кодпоинтах.
Отсюда и странности с кириллицей: половина символа сравнивалась отдельно.

Сдвиг массива (`shiftcounter = round(phr_count * analyze(...))`) — это
попытка «поднять» похожие фразы в начало списка. Ровно то, что сейчас
делает сортировка по score, но без математики.

`Makefile.win` — от wxDev-C++, пути вида `Z:/DEV/IDE/wxDev-Cpp/...`
(сетевой диск, которого давно нет).

## `2012-oglconsole` — консоль на OpenGL

Сторонняя библиотека Donny Viszneki (GPL2), `oglconsole.c` — 982 строки.
Рисует консоль поверх OpenGL-контекста со своим встроенным bitmap-шрифтом.

**Почему не пошло.** OGLCONSOLE требует живой OpenGL-контекст и работает
только с ним. Проект же хотел рисовать текст через SDL_ttf (настоящий TTF,
кириллица, произвольный размер). Держать два разных механизма вывода
ради одной консоли — неоправданно.

**Что осталось полезным.** `ConsoleFont.c` (1487 строк) — пример того,
как упаковать bitmap-шрифт в C-массив. Пригодилось при генерации
`src/icon_rgba.h`.

Лицензия GPL2 несовместима с MIT: объединять этот код с основной линией
в одну работу нельзя. Поэтому он остаётся в `archive/` как справочный
материал и в сборку не входит.

## `2012-sdl-resize` — ресайз поверхностей

`resize.c` (640 строк) + `resize.h`. Библиотека фильтрованной интерполяции
поверхностей SDL: box, triangle, bell, B-spline, hermite, Mitchell, Lanczos3.
Авторы: Dale Schumacher (1991), Ray Gardener (1999), Dave Olsen (2006),
Kevin Baragona.

**Зачем было нужно.** Идея: рисовать текст в маленьком разрешении и
растягивать фильтром, получая «сглаженный пиксельный» вид. Или наоборот —
уменьшать большие поверхности.

**Почему не пошло.** SDL_ttf сам умеет рендерить в нужном размере с
нормальным антиалиасингом (`TTF_RenderUTF8_Blended`). Ресайз готовой
текстуры давал мыло, а не чёткость. В SDL2 эта задача вообще решается
`SDL_RenderSetLogicalSize` и масштабированием текстуры на GPU.

Файлы сохранены как рабочий пример реализации фильтров — если понадобится
масштабировать спрайты, тут всё готово.

| `hello.exe` | PE-дата **03.01.2013 23:19:35** |
| `runtime/` | SDL.dll, SDL_ttf.dll, libfreetype-6.dll, пустые stdout/stderr |

### Что случилось 3 января

Ночь с 3 на 4 января 2013 — попытка вынести обработку событий из `main()`
в отдельный файл. Результат — **сломанная сборка**, и это видно в бинаре.

Три состояния одного файла:

```
A. hello_c_backup_030113.7z   655 строк   ← рабочее
B. Hello-0.1.zip / git HEAD   649 строк   ← сломано
```

Диффы A → B:

```diff
 #include <GL/glu.h>
+
+#include "helleventcontrol.c"

-    flags = SDL_OPENGL;// | SDL_FULLSCREEN;
+    flags = SDL_SWSURFACE; //SDL_OPENGL;

-    setup_opengl( w, h );
+//  setup_opengl( w, h );

+      process_events();
+      /*
       while(SDL_PollEvent(&event)){      ← весь разбор событий
         ...                              ← закомментирован
       }
+      */
```

А `helleventcontrol.c` содержит заглушку:

```c
void process_events( void )
{
    SDL_Event event;
    while( SDL_PollEvent( &event ) ) {
        switch( event.type ) {
        case SDL_KEYDOWN:
            /* Handle key presses. */
            break;
        case SDL_QUIT:
            /* Handle quit requests (like Ctrl-c). */
            break;
        }
    }
}
```

**Итог:** программа рисуется, но не реагирует ни на что. Клавиши
«проглатываются» пустым `switch`. Это подтверждается дизассемблером
`hello.exe` — функция `process_events` по адресу `0x401c76` сравнивает тип
события с `2` (`SDL_KEYDOWN`) и `12` (`SDL_QUIT`) и в обоих случаях просто
выходит из `switch`.

Ещё две детали, обе — источник будущих проблем:

1. `hello.c` в UTF-8, `helleventcontrol.c` в **cp1251**. Одна единица
   трансляции, две кодировки. Компилятор это проглотил, потому что весь
   cp1251-текст — в комментариях.
2. `#include "keysim.c"` и `#include "acsman.c"` — включение `.c` файлов
   в `.c`. Работает, но ломает раздельную компиляцию и делает линковку
   загадкой.

### Строки, которых нет в бинаре

В `hello.c` есть `"Иди нахуй, окда?"` — но в `hello.exe` её **нет**.
Объяснение простое: строка находится внутри закомментированного блока,
а комментарии в бинарь не попадают. Это ещё одно подтверждение, что
`hello.exe` собран именно из сломанной версии.

А вот `"Здарова, "`, `" ёпта"` и `"ВНЕЗАПНО: Доступ есть %i"` в бинаре
присутствуют — они в живом коде.

### `keysim.c` — почему 1546 строк

SDL 1.2 отдаёт `event.key.keysym.unicode` как один кодпоинт. Чтобы получить
UTF-8, нужна таблица. В `keysim.c` лежит массив `keysymcodes[]` на ~1100
кодпоинтов и параллельный `keysymletters[][]` со строками UTF-8, плюс
бинарный поиск `unicsym2char()`. Сгенерировано вручную.

В SDL2 это не нужно: `SDL_TEXTINPUT` отдаёт готовую UTF-8-строку,
включая IME и композицию. 1546 строк превратились в один вызов.

### `acsman.c` — что это было

414 строк «почти C++» на C: `FString` (строка с капитализацией/заменой),
`FScannerSTCK` (структура с 40 указателями на функции), `FScriptPositionSTCK`
(позиция в скрипте с сообщениями об ошибках). Начато как переписывание
`sc_man.c` из Heretic 2 — предполагался скриптовый язык для бота.

Дошло только до `FScriptPosition_Message()`, которая умеет выводить цветное
сообщение в общий массив текстовых поверхностей. Использовалась ровно
один раз:

```c
FScriptPosition_Message(FScriptPosition, font, &changed, &text_solid_length,
                        text_solid, 310, BUF_SIZE, "ВНЕЗАПНО: Доступ есть %i", 200);
```

Скриптовый язык не появился. Файл сохранён как памятник замаху.

## `2013-autotools` — сборочная обвязка

`configure`, `Makefile.in`, `aclocal.m4`, `depcomp`, `install-sh`, `missing`,
`config.status`, `config.h`, `stamp-h1`, `.whitesource`.

**Состояние: нерабочее.** В `configure.ac`:

```
AC_INIT([amhello], [1.0], [bug-automake@gnu.org])
```

`amhello` — имя из учебного примера Automake. Дальше идёт блок проверки SDL,
вклеенный **после** `AC_OUTPUT` и без перевода строк:

```
AC_OUTPUT
dnl Check for SDL SDL_VERSION=1.2.0 AM_PATH_SDL($SDL_VERSION,
:, AC_MSG_ERROR([*** SDL version $SDL_VERSION not found!])

) CFLAGS="$CFLAGS $SDL_CFLAGS" LIBS="$LIBS $SDL_LIBS"
```

То есть `AM_PATH_SDL` вызывается уже после генерации выходных файлов —
работать это не может. Плюс `-Werror` в `AM_INIT_AUTOMAKE`, что гарантирует
падение на любом предупреждении.

Сгенерированные файлы (`configure`, `Makefile.in`, `aclocal.m4`) закоммичены
вместе с исходниками — классическая ошибка. В 2026-м это заменено на CMake,
а обвязка убрана в архив целиком, включая `config.status` (он содержит
абсолютные пути машины 2013 года).

## `2015-03-primegen` — генератор простых чисел

Отдельная идея, к боту отношения не имеет: «Hello» как учебная песочница
для Win32 + OpenGL.

### `console-gen`

`hello.cpp` (61 строка), консоль, `system("pause")`, лог в `hello.log`.

```cpp
int FindPrimeNumber()
{
    do {
        n1 << rand();                 // ← сдвиг на случайное число бит
        if (PrimeNumber(n1) == 1)
            n1prime << n1;
        n2 << rand();
        if (PrimeNumber(n2) == 2)     // ← сравнение с 2, а функция возвращает 0/1
            n2prime << n2;
        n << n1prime + n2prime;
        std::cout << n << std::endl;
    } while (PrimeNumber(n) == 1);
    return Success = 1;
}
```

Тут сразу четыре проблемы:

1. `n1 << rand()` — сдвиг на случайное число от 0 до `RAND_MAX`. Для `int`
   это неопределённое поведение почти всегда.
2. `PrimeNumber(n2) == 2` — функция возвращает `0` или `1`, `2` не бывает
   никогда. Ветка мертва.
3. `n1prime`, `n2prime`, `n` не инициализированы — читаются до записи.
4. `PrimeNumber` внутри цикла возвращает `1` при `i > sqrt(number)`, но
   проверка `i == number` недостижима.

Ранняя версия `_old/090315_hello.cpp` проще и честнее:

```cpp
nPrime += rand()%INT_MAX+2;   // переполнение int гарантировано
```

Идея была: «генерировать простые числа и любоваться». Дожило до
двух итераций.

### `gl-primegen`

`main.cpp` (287 строк): Win32-окно + OpenGL через `wglCreateContext`,
`isPrime`, `starmake`, `DrawGLScene_Triangle`, `DrawGLScene_Starfield`,
`ConsoleWorker`, логирование в файл.

`_old/` — шесть итераций за 7–8 марта 2015:

| Файл | Строк | Что добавилось |
|---|---|---|
| `main_070315_1303.cpp` | 176 | Win32-окно + `EnableOpenGL`/`DisableOpenGL` |
| `main_070315_1707.cpp` | 250 | + `Logger_WriteFile`, `DrawGLScene` |
| `main_070315_1913.cpp` | 274 | правки рисования |
| `main_070315_2206.cpp` | 284 | + `starmake`, `DrawGLScene_Starfield`, `ConsoleWorker` |
| `main_080315_0250.cpp` | 299 | + `isPrime`, `main` собран целиком |
| `main_080315_1426.cpp` | 289 | финальная сборка (`hello-rly1.exe`) |

**Ключевой баг финала:** цикл сообщений `while(GetMessage(...))` стоит
**до** цикла генерации простых чисел. То есть числа начинают считаться
только после закрытия окна. Программа, которая должна что-то показывать,
показывает пустое окно.

`hello.log` в архиве содержит ровно одну строку — `Info: OpenGL initialized`:
до `Info: Application closed` дело не дошло, процесс убили.

Собиралось в wxDev-C++ 7.4.2.569, линковка `-lopengl32 -lglut32 -lglu32
-lgdi32 -mwindows`, пути `Z:/DEV/IDE/wxDev-Cpp/`.

## Как пополнять архив

1. Кладёшь коллекцию в `refs/` (в git не попадает).
2. Определяешь происхождение: PE-даты (`objdump -p`), символы (`objdump -t`),
   строки (`strings`), диффы с известными версиями.
3. Создаёшь `archive/<год-месяц-идея>/`, кладёшь файлы **как есть**.
4. Пишешь секцию в этом файле: что это, откуда, что подтверждено, что
   осталось догадкой.
5. `refs/` снова пустеет.

Скрипты для разбора — в `tools/re/`:

| Скрипт | Назначение |
|---|---|
| `pe_info.py` | секции, дата сборки, импорты, символы PE |
| `pe_strings.py` | ASCII-строки по секциям |
| `dump_utf8.py` | UTF-8-строки по секциям (кириллица) |

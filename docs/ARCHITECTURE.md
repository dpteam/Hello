# Архитектура

Документ описывает, как устроен код основной линии, почему решения приняты
именно такие и где проходит граница между «логикой» и «SDL».

## Принципы

1. **Логика без SDL.** Всё, что можно протестировать без окна, живёт
   в отдельной статической библиотеке `hello_core` и не знает про SDL.
   Это `utf8`, `input`, `chat`, `markov`, `text_metrics`, `config`.
2. **Никаких глобальных состояний.** Каждый модуль — структура с явным
   созданием/уничтожением. `App` собирает их вместе.
3. **Ошибка не убивает процесс.** Функция возвращает `bool`/`NULL`, вызывающий
   решает. Исключение — старт приложения: без шрифта или окна работать нечем.
4. **UTF-8 везде.** Границы символов уважаются при удалении, вставке,
   переполнении буфера и переносе строк.

## Слои

```
┌──────────────────────────────────────────────────────────────┐
│  main.c          аргументы командной строки → Config          │
├──────────────────────────────────────────────────────────────┤
│  app.c           окно, цикл событий, команды, состояние       │
├───────────────────────────┬──────────────────────────────────┤
│  render.c / view.c        │  theme.c                          │
│  текст → текстура,        │  цветовые схемы                   │
│  перенос, прокрутка       │                                   │
├───────────────────────────┴──────────────────────────────────┤
│  platform.c      окно, шрифт, иконка, пути — общее для всех   │
├──────────────────────────────────────────────────────────────┤
│  chat.c          память фраз, выбор ответа                    │
│     ├── markov.c         цепь Маркова                         │
│     └── text_metrics.c   Дайс, Жаккар, Левенштейн, Джаро      │
├──────────────────────────────────────────────────────────────┤
│  utf8.c          декодер/энкодер, casefold, «шум»             │
│  input.c         строка ввода + история                       │
│  config.c        ini-парсер                                   │
└──────────────────────────────────────────────────────────────┘
```

`hello_core` = `chat`, `markov`, `text_metrics`, `utf8`, `input`, `config`.
`hello` = `main`, `app`, `platform`, `render`, `view`, `theme` + SDL3 + SDL3_ttf.

### `platform`

Всё, что нужно любому приложению проекта и не относится к конкретной идее:
подключение консоли на Windows, поиск шрифта (сначала конфиг, потом
стандартные места рядом с бинарником и в системе), разрешение
относительных путей, иконка окна, создание окна и рендерера.

Вынесено отдельно, чтобы варианты (`календарь`, `куб`) не копировали
этот код. `app.c` использует те же функции.

## Поток одного сообщения

```
SDL_TEXTINPUT ──► input_insert() ──► Input.buf
                                        │
Enter ──► submit()                      │
   ├── echo «› текст» в View            │
   ├── input_remember() ──► история     │
   ├── input_clear()                    │
   ├── начинается с '/'? ──► run_command()
   └── иначе:
        ├── chat_learn()    ──► память + дообучение цепи
        └── schedule_reply() ──► pending_at = now + задержка
                                        │
(через 220–900 мс)                      ▼
                        deliver_reply() ──► chat_reply()
                                             ├── метрики по всем фразам
                                             ├── BM25
                                             ├── урновый штраф
                                             └── либо Марков, либо
                                                 встроенная реплика
                                        ──► View
```

Задержка ответа — не «для реализма», а чтобы интерфейс успевал
перерисоваться: полный перебор 4000 фраз × BM25 занимает заметное время,
и без отложенного ответа окно подвисало бы на кадр.

## Модули

### `utf8`

Полный декодер с проверками: overlong-последовательности, суррогаты,
значения выше `U+10FFFF` отбраковываются. `utf8_clip` обрезает строку по
границе символа — используется при переполнении строки ввода.

`utf8_casefold` — упрощённый casefold для ASCII, латиницы-1,
Latin Extended-A, кириллицы и греческого. Полный Unicode CaseFolding
не нужен: бот говорит на русском и английском.

`utf8_is_noise` отделяет «шум» (пробелы, пунктуация, управляющие) от
значащих символов. Это единственное место, где решается, что считать
словом.

### `input`

Строка ввода хранится как UTF-8 в динамическом буфере, курсор — байтовое
смещение на границе символа. Все операции (`insert`, `backspace`, `delete`,
`left`, `right`) сохраняют это инвариантное условие.

История — кольцевой список до 64 записей, дубликаты подряд не добавляются.
При навигации черновик сохраняется и восстанавливается — как в оболочке.

### `text_metrics`

Чистая математика над массивами `uint32_t` (кодпоинты). Никаких строк —
это позволяет тестировать формулы отдельно от текста и не разбирать
UTF-8 на каждом шаге.

Реализации:

- **Дайс** и **Жаккар** — сортировка биграмм + слияние (`O(n log n)`).
- **Левенштейн** — две строки ДП (`O(n·m)` память `O(min)`), с ранним
  выходом по `max_distance`.
- **Дамерау** — полная матрица, но только для строк ≤ 256 символов,
  иначе деградирует до Левенштейна.
- **Джаро–Уинклер** — окно совпадения + бонус за префикс.
- **Softmax** с вычитанием максимума (устойчивость к большим числам).
- **Степенное распределение** `p ∝ w^(1/T)` — для температуры Маркова.
- **Энтропия Шеннона** — для диагностики.

### `markov`

Цепь порядка до 3. Состояние — последние `order−1` слов. Хранилище:

- словарь `слово → uint32_t id` (хеш FNV-1a),
- `unigram[id]` — список переходов из одного слова,
- `bigram_index[(a,b)] → список` — переходы из пары.

Сглаживание — «глупый бэкофф»: пробуем пару, потом слово, потом начало
предложения. Это дешевле и предсказуемее Kneser-Ney, а для 4000 фраз
разницы не видно.

Токены `0` и `1` зарезервированы под `<s>` и `</s>`.

### `chat`

Собирает всё вместе:

- **Память** — массив фраз (23 встроенные + выученные), дубликаты
  отсекаются без учёта регистра и пунктуации.
- **Переполнение** — резервуарная выборка: при 4096 фразах новая фраза
  с вероятностью `max/seen` вытесняет случайную выученную. Память остаётся
  репрезентативной, а не «последние N».
- **Оценка** — `0.7·похожесть + 0.3·BM25`, затем урновый штраф.
- **Выбор** — топ-6 кандидатов, отсечение по `0.72·лучший`, взвешенный
  случайный выбор `p ∝ score³`.
- **Импровизация** — если лучшая оценка ниже `0.28`, с вероятностью,
  растущей от объёма памяти, вызывается Марков.

### `view`

Логические строки (`ViewLine`) хранятся как UTF-8 и пере-верстаются
в визуальные (`ViewRow`) с готовыми текстурами. Пере-верстка происходит:

- при добавлении строки,
- при смене темы,
- при изменении размера окна.

Не в каждом кадре. Перенос — по словам, с откатом на «хотя бы один символ»,
если слово шире окна. Это гарантирует прогресс и не даёт бесконечного цикла.

### `app`

Владеет всем состоянием. Цикл:

```
poll events → отложенный ответ? → отрисовать → посчитать FPS → (delay)
```

При `vsync = false` и `fps_limit > 0` добавляется `SDL_Delay` до целевого
времени кадра. При `vsync = true` ждём `SDL_RenderPresent`.

## Принятые решения

**Почему SDL3, а не SDL 1.2?** SDL 1.2 не развивается с 2012 года и
собирается только из msys2. SDL3 есть везде, даёт `SDL_EVENT_TEXT_INPUT`
с готовым UTF-8 и нормальный рендерер.

**Почему SDL3, а не SDL2?** SDL3 — актуальная ветка: float-геометрия
(`SDL_FRect`), нормальные события вместо `SDL_WindowEvent`, `SDL3/SDL.h`
в подкаталоге. Плюс это снимает ловушку с `sdl2-compat`: MSYS2 одно
время отдавал «SDL2» как прослойку над SDL3, которая падала без
`SDL3.dll`. Собираясь сразу на SDL3, мы этой прослойки не касаемся.

**Почему `SDL_EVENT_TEXT_INPUT`, а не `keysym.unicode`?** В SDL 1.2
приходилось вручную собирать UTF-8 из кодпоинта и изобретать `keysim.c`
на 1546 строк с таблицей соответствий. SDL3 отдаёт готовую строку —
и с IME, и с композицией.

**Почему `SDL_StartTextInput` вызывается явно?** В SDL3 текстовый ввод
выключен по умолчанию: «Text input events are not received by default»
(документация `SDL_keyboard.h`). В SDL2 он был включён, поэтому при
переезде вызов легко потерять — и тогда получается тихая ошибка:
`SDL_EVENT_KEY_DOWN` приходит (Enter, стрелки, Backspace работают),
а `SDL_EVENT_TEXT_INPUT` нет, и символы не набираются. Вызов стоит
в `hello_open_window`, а `--selftest` проверяет, что он сработал.

**Почему свой UTF-8, а не ICU/utf8proc?** Нужно ровно шесть операций,
и они занимают 350 строк. Внешняя зависимость весила бы больше, чем экономила.

**Почему не ветки для архивных вариантов?** Ветки подразумевают слияние и
общую историю. Это разные идеи, которые никогда не встретятся: куб на
OpenGL, консоль на OpenGL, генератор простых чисел. Каталоги честнее —
их видно в дереве и они не мешают сборке.

**Почему `refs/` в `.gitignore`?** Это рабочий стол для разбора: туда
кидаются архивы и бинарники, оттуда они уезжают в `archive/` уже
разобранными. Мусор в истории не нужен.
